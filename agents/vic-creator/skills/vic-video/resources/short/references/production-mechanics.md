## Job contract

Keep inputs and new outputs in one owned job/revision folder. Copy approved inputs there without changing originals. Create `job.json` with:
- `audio`: WAV narration or separately finished mix, `envelope`: normalized10ms narration-only JSON array, `chunks`: measured display-text JSON (list or object with `chunks`), separate from immutable narration chunks when using keypoints. New structured jobs use `visual_plan`; do not also author scenes.js.
- `duration_s`: finite30fps-aligned total covering ALL audio/pauses/tail. Each display chunk has start_s,end_s,visible_text in the selected text mode. Main-point intervals follow the relevant spoken idea and may span narration chunks. Keep original speech/chunks separately. In optional verbatim mode, preserve the approved caption string including whitespace; phrase timing remains estimated, not forced word alignment. Main points are not subtitles. When subtitles are selected, verify every spoken chunk is covered and actual glyph pixels appear during speech; a phrase JSON or renderer trace alone does not prove visible text. Remove the old keypoint chip rather than stacking duplicate bottom text.
- `shots`: contiguous `{id,start,end,bg,pose,hidePresenter}` records from0 through total duration with unique IDs; calibrated poses remain unchanged. Optional per-shot `presenter: {"x":28,"y":1578,"width":315}` controls supporting/hero size and placement; `hidePresenter:true` removes it for demos/evidence. Choose by content and reserve space before placing captions/graphics. Defaults are supporting staging, not a mandatory host size. Preparation validates finite image bounds, and source QA rejects presenter/caption overlap; changing size uses the same lip-registration transform.
- `assets`: alias→job-relative image path, relevant to the current story; `rigs`: optional measured character cues and landmarks. Coherent optional palette, no compulsory green anchor.
- `visual_plan`: job-relative structured JSON linking every shot/object/required illustration/action to its execution. Read [visual-plan](visual-plan.md) for exact schema and semantic operations; this replaces new job-authored scenes.js on the supported production route. Existing frozen legacy files remain preserved. No copying previous-topic timelines or doing ad-hoc paragraph scenes as a fallback.
